\begin{abstract}
Macro placement fixes the positions of large blocks (memories, IP cores) on a chip canvas and strongly
determines the final power, performance and area (PPA). Two recent learning-based approaches attack the
weaknesses of reinforcement-learning (RL) ``placers'' that build a layout from an empty canvas. The
first is a diffusion model that generates all macro positions at once and is trained only on synthetic
data \citep{lee2025diffusion}. The second is \emph{MaskRegulate}, which recasts RL as a
\emph{regulator} that refines an existing placement using dense, exact rewards for wirelength and
\emph{regularity} \citep{xue2024maskregulate}. We review both works and identify three gaps:
(i) timing and congestion are measured only after placement and never shape the RL reward,
(ii) the wirelength--regularity trade-off is fixed by a single hand-chosen coefficient, and
(iii) the regulator's outcome is bounded by the placement it starts from. We propose two extensions.
\textbf{Direction 1} gives the regulator new information about timing and routing congestion, through
a \emph{TimingMask} and a \emph{CongestionMask}, and rewards it for improving both.
\textbf{Direction 2} replaces the single trade-off with a multi-objective approach: one
preference-conditioned regulator that returns a set of placements covering different trade-offs. We
also propose starting the regulator from a diffusion-generated placement, which links the two papers.
Finally, we describe how these ideas will be evaluated on the ICCAD 2015 benchmarks.
\end{abstract}

\section{Introduction}

Physical design turns a logical netlist into a manufacturable layout. Its first major step,
\emph{placement}, assigns coordinates to every component. Modern chips contain hundreds to thousands of
\emph{macros} and millions of small \emph{standard cells}, so placement is usually done in two stages:
macros first, then cells around them. Because macros are large and highly connected, their positions
largely decide how long the wires are, where routing congestion appears, and whether signals arrive
within the clock period (timing).

Google's RL work \citep{mirhoseini2021graph} made macro placement a popular RL benchmark: an agent places
macros one at a time on a grid and receives a reward based on wirelength. Follow-up placers
\citep{lai2022maskplace, lai2023chipformer, geng2024efficientplace} improved representations and sample
efficiency, but three problems remain:
\begin{itemize}
  \item RL placers must be trained per circuit, which takes hours.
  \item They generalise poorly, because little public data exists.
  \item They make early, irreversible decisions with incomplete information: the first macro is placed
  before the agent knows where its neighbours will go.
\end{itemize}

This project studies two papers that respond to these problems in opposite ways. \textbf{Paper A}
\citep{lee2025diffusion} abandons RL and trains a denoising diffusion model that places \emph{all}
objects simultaneously and zero-shot. \textbf{Paper B}, MaskRegulate \citep{xue2024maskregulate}, keeps
RL but changes its job. The policy \emph{refines} an existing placement instead of building one from
scratch, and a \emph{regularity} objective pushes macros towards the canvas periphery.

\paragraph{Contributions of this report.}
\begin{enumerate}
  \item A review of both papers and a gap analysis based on the papers' own reported results
  (Section~\ref{sec:lit}).
  \item \textbf{Direction 1:} a timing- and congestion-aware regulator with two new input masks and
  reward terms (Section~\ref{sec:d1}).
  \item \textbf{Direction 2:} a multi-objective regulator that produces a set of trade-off placements
  from a single trained policy (Section~\ref{sec:d2}).
  \item A plan for evaluating both directions (Section~\ref{sec:protocol}).
\end{enumerate}

\section{Background}
\label{sec:bg}

\paragraph{Netlist and placement.} A netlist is a hypergraph $\mathcal{H}=(V,E)$. Each net $e\in E$
connects a set of pins $P_e$ on objects in $V=V_{\mathrm{mac}}\cup V_{\mathrm{cell}}\cup V_{\mathrm{io}}$.
Macro $i$ has width $w_i$ and height $h_i$. A macro placement
$s=\{(x_i,y_i)\}_{i=1}^{N}$ gives the lower-left corner of each of the $N$ macros. It is \emph{legal}
if macros lie inside the canvas $[0,X_{\max}]\times[0,Y_{\max}]$ and their rectangles do not overlap.

\paragraph{Half-perimeter wirelength (HPWL).}
\begin{equation}
\mathrm{HPWL}(s)=\sum_{e\in E}\Big(\max_{p\in P_e}x_p-\min_{p\in P_e}x_p\Big)+\Big(\max_{p\in P_e}y_p-\min_{p\in P_e}y_p\Big).
\label{eq:hpwl}
\end{equation}
It is cheap to compute and is the main wirelength proxy in both papers.

\paragraph{Regularity} \citep{xue2024maskregulate}. The regularity of macro $i$ is the sum of its
distances to the nearest vertical and horizontal canvas edges:
\begin{equation}
\mathrm{Reg}(s)=\sum_{i=1}^{N}\Big[\min\{x_i,\,X_{\max}-x_i-w_i\}+\min\{y_i,\,Y_{\max}-y_i-h_i\}\Big].
\label{eq:reg}
\end{equation}
It is zero for a macro in a corner and largest at the centre, so lower is better.

\paragraph{Timing.} A static timing analysis (STA) tool computes when each signal arrives and compares
it with the time it is required, which is set by the clock period $T$. The difference is the
\emph{slack}; a negative slack means the signal is late. Two standard summaries are used: the
\emph{worst negative slack} (WNS), which is the single latest path, and the \emph{total negative
slack} (TNS), which is the sum over all late paths. For both, values closer to zero are better.

\paragraph{Reinforcement learning.} An agent observes a \emph{state}, takes an \emph{action} and
receives a \emph{reward}. It learns a \emph{policy} that maximises the total reward over an episode.
Both MaskRegulate and our extensions train the policy with PPO \citep{schulman2017ppo}, a standard
and stable policy-gradient algorithm.

\section{Literature Review}
\label{sec:lit}

\subsection{Classical and learning-based macro placement}
\emph{Analytical} placers such as DREAMPlace \citep{lin2021dreamplace} relax placement into a smooth
problem (wirelength plus a density penalty) and solve it with GPU gradient descent. They are fast, but
they tend to cluster macros in the centre and can stall in local optima. AutoDMP
\citep{agnesina2023autodmp} tunes DREAMPlace's settings with Bayesian optimisation, and DREAMPlace~4.0
\citep{liao2023dreamplace4} makes it timing-driven by re-weighting critical nets. \emph{Black-box}
methods such as WireMask-BBO \citep{shi2023wiremask} search placements guided by a wire mask.
\emph{RL placers}, including GraphPlace \citep{mirhoseini2021graph}, MaskPlace \citep{lai2022maskplace},
ChiPFormer \citep{lai2023chipformer} and EfficientPlace \citep{geng2024efficientplace}, place macros
sequentially on a grid. Independent assessments have questioned how well RL placers' proxy gains carry
over to real PPA \citep{cheng2023assessment}.

\subsection{Paper A: Chip Placement with Diffusion Models \citep{lee2025diffusion}}
\textbf{Objective.} Train a model once, offline, that can then place the macros of \emph{any} new chip
in a few minutes, without retraining it for that chip.

\textbf{Main idea.} The paper uses a \emph{diffusion model}, the same kind of generative model used by
modern image generators. Generation starts from macros scattered at random positions. The model then
nudges all of them a little at a time, over many small steps, until a clean, compact layout emerges.
Because every macro moves together, no early decision is locked in, unlike in sequential RL placers.

\textbf{Training data.} Real chip designs are confidential, so there is very little data to learn
from. The authors solve this by running the problem in reverse: they first scatter blocks on a canvas
and only then add wires, mostly between blocks that are already close together. The layout they
started from is therefore a good placement for the circuit they generated. This gives an unlimited
supply of (circuit, good placement) examples at almost no cost.

\textbf{Guidance.} While generating a layout, the model is gently steered towards shorter wires and
away from overlapping macros, without any retraining.

\textbf{Reported results.} On standard academic benchmarks (IBM and ISPD 2005), the paper reports:
\begin{itemize}
  \item placements in minutes per chip, instead of the hours needed by RL methods;
  \item substantially shorter wirelength and less congestion than earlier RL and search-based placers;
  \item results slightly better than DREAMPlace, a widely used analytical placer.
\end{itemize}

\textbf{Shortcomings.}
\begin{itemize}
  \item It only measures quick estimates (wirelength, congestion). Timing is never checked.
  \item It cannot easily trade extra compute for better quality. The authors suggest RL fine-tuning
  as future work.
  \item Overlaps are discouraged but not strictly prevented.
\end{itemize}

\subsection{Paper B: MaskRegulate \citep{xue2024maskregulate}}
\textbf{Objective.} Use RL to \emph{refine} a placement produced by DREAMPlace rather than create one,
and optimise for real PPA rather than HPWL alone.

\textbf{MDP.}
\begin{itemize}
  \item An episode visits each macro once, in a rule-based order.
  \item The state is a set of $224\times224$ image masks for the current macro and the next one:
  \begin{itemize}
    \item The \emph{PositionMask} marks feasible cells; only already-adjusted macros count as obstacles.
    \item The \emph{WireMask} gives the exact change in HPWL for each cell, normalised to $[-1,1]$.
    \item The \emph{RegularMask} gives the change in regularity.
  \end{itemize}
  \item The action chooses one of $224^2$ cells for the current macro.
  \item The reward is $r=\alpha\,r_{\mathrm{wire}}+(1-\alpha)\,r_{\mathrm{reg}}$, where both terms are
  normalised to $[0,1]$ and $\alpha=0.7$.
\end{itemize}
The policy fuses masks pixel-wise with $1\times1$ convolutions and combines them with a ResNet-18
encoder/decoder, before masking infeasible cells and applying a softmax. Training uses PPO. Because every
other macro already has a position, the effect of each move is computed exactly. This removes the
incomplete-information and sparse-reward problems of placers.

\textbf{Reported results.} On the ICCAD 2015 \emph{superblue} circuits \citep{kim2015iccad}, evaluated
with Cadence Innovus, MaskRegulate has the best average rank on all eight metrics. Compared with
MaskPlace, it improves routed wirelength by 17.08\%, horizontal and vertical overflow by 73.08\% and
38.81\%, WNS by 18.35\%, TNS by 37.89\%, and NVP by 46.17\%. It also generalises to unseen chips and
can refine the outputs of other placers.

\textbf{Shortcomings.}
\begin{itemize}
  \item \emph{Timing and congestion are never in the reward.} The authors list overlooking ``global
  wirelength and timing metrics during the training process'' as a limitation. Their results agree:
  \begin{itemize}
    \item The average WNS and TNS ranks are both 1.875, against 1.0--1.125 for regularity, routed
    wirelength and horizontal overflow.
    \item AutoDMP has better WNS on superblue4, 16 and 18.
    \item On superblue7, MaskRegulate's vertical overflow (0.64\%) is about double that of MaskPlace
    (0.33\%) and WireMask-EA (0.35\%).
  \end{itemize}
  \item \emph{A single trade-off.} $\alpha$ is fixed by hand. The authors' sweep shows different
  $\alpha$ give different trade-offs, and they name multi-objective optimisation for different chip
  preferences as future work.
  \item \emph{Dependence on the start.} The regulator edits locally, so a poor initial placement bounds
  the outcome.
  \item The grid is discrete, training takes about 1{,}000 PPO episodes per chip, and macro aspect
  ratio is ignored.
\end{itemize}

\subsection{Comparison and research gaps}
Table~\ref{tab:compare} summarises the two papers. They are complementary: Paper A is a fast,
zero-shot \emph{drafter} with no notion of PPA beyond HPWL, while Paper B is an accurate
\emph{editor} that needs a draft and optimises only two proxies. Concurrent work, FlowPlace
\citep{xie2026flowplace}, folds a periphery prior into the synthetic data of a flow-matching
generator. It uses neither RL fine-tuning nor multi-objective selection. We target three gaps:
\begin{description}
  \item[G1] Timing and congestion should enter the regulator's \emph{state and reward}, not only its
  evaluation. This is Direction~1.
  \item[G2] Designers need a \emph{set} of trade-off placements, not one $\alpha$. This is Direction~2.
  \item[G3] The regulator's outcome is bounded by its start, which motivates a diffusion-generated
  start (Section~\ref{sec:g3}).
\end{description}

\section{Proposed Methodology}
\label{sec:method}

We keep MaskRegulate's overall framework and extend it in two directions. Figure~\ref{fig:pipeline}
shows the complete flow:
\begin{enumerate}
  \item An initial macro placement is produced, either by DREAMPlace (as in MaskRegulate) or by the
  diffusion model of Paper A.
  \item An RL \emph{regulator} refines this placement one macro at a time.
  \item Standard cells are placed around the fixed macros with DREAMPlace.
  \item The final layout is routed and its timing is checked.
\end{enumerate}
Our changes are all inside step~2: what the regulator \emph{sees} (its input masks) and what it is
\emph{rewarded} for.

\subsection{How the regulator works}
\label{sec:mdp}
The chip canvas is divided into a grid of cells. Macros are visited one at a time, largest first. In each
episode, every macro is visited exactly once:
\begin{itemize}
  \item \textbf{What the agent sees (state).} A set of grid-shaped ``masks'' for the current macro. Each
  mask answers one question for every grid cell, for example: ``Is this spot free?'' (PositionMask) or
  ``How would wirelength change if the macro moved here?'' (WireMask).
  \item \textbf{What the agent does (action).} It picks a free grid cell and moves the current macro
  there.
  \item \textbf{What the agent gets (reward).} The improvement that the move produced in each objective,
  combined with weights:
  \begin{equation}
  r=w_{\mathrm{wire}}\,r_{\mathrm{wire}}+w_{\mathrm{reg}}\,r_{\mathrm{reg}}+w_{\mathrm{tim}}\,r_{\mathrm{tim}}+w_{\mathrm{cong}}\,r_{\mathrm{cong}}.
  \label{eq:reward}
  \end{equation}
  MaskRegulate uses only the first two terms ($w_{\mathrm{wire}}=0.7$, $w_{\mathrm{reg}}=0.3$). The
  timing and congestion terms are our additions.
\end{itemize}

Each reward term is scaled by the objective's starting value so that terms with different units are
comparable. The per-move rewards also add up exactly to the total improvement over the whole episode.
This means the agent receives frequent, accurate feedback, and it is still being trained to optimise
the \emph{final} layout. It also means that a new objective can be added to the regulator as long as we
can compute how each possible move would change it. That is exactly what the two new masks below
provide.

The policy network (a CNN) and the training algorithm (PPO) are kept as in MaskRegulate. Only the input
masks and the reward change.

\subsection{Direction 1: timing- and congestion-aware regulation}
\label{sec:d1}

\paragraph{Motivation.} MaskRegulate pushes macros towards the chip edges (regularity). This clears the
centre for routing, but it can stretch the wires on timing-critical paths that pass through those
macros. Its own results show timing as its weakest metric. We therefore give the regulator direct
information about timing and congestion.

\subsubsection{TimingMask}
\begin{itemize}
  \item \textbf{Delay model.} Wire delay grows faster than wire length. For a simple driver-and-wire
  model (the Elmore delay, \citealp{elmore1948transient}), it has a constant part, a part proportional
  to the length $\ell$, and a part proportional to $\ell^2$:
  \begin{equation}
  d(\ell)\approx d_0+a\,\ell+b\,\ell^2 .
  \end{equation}
  A long wire is therefore disproportionately slow. Moving a macro to the edge can create exactly such
  long wires.
  \item \textbf{Which paths matter.} A static timing analysis (STA) tool (OpenSTA or OpenTimer) lists
  the most critical paths and their delays. The STA is re-run every few training episodes, not after
  every move, to keep it affordable.
  \item \textbf{Timing cost.} We add up how much each critical path exceeds the clock period $T$. A small
  safety margin also counts paths that are \emph{nearly} late:
  \begin{equation}
  \text{Timing cost}=\sum_{\text{critical paths}}\max\big(0,\ \text{path delay}-0.95\,T\big).
  \end{equation}
  \item \textbf{The mask.} Moving a macro only changes the two wires connecting it to its neighbours on
  each path. So for every grid cell we can compute exactly how the timing cost would change. This
  produces the TimingMask, which works the same way as MaskRegulate's WireMask.
  \item \textbf{Cheaper alternative.} Instead of tracking whole paths, give more weight to nets that lie
  on critical paths inside the existing WireMask. This is similar to how DREAMPlace~4.0 makes
  placement timing-driven \citep{liao2023dreamplace4}. We will compare both versions.
\end{itemize}

\subsubsection{CongestionMask}
\begin{itemize}
  \item \textbf{Routing demand.} RUDY \citep{spindler2007rudy} estimates how many wires pass through each
  region of the chip by spreading each net's wire evenly over its bounding box. Total demand over the
  whole chip equals the total wirelength. Wirelength alone therefore controls how \emph{much} demand
  there is, but not \emph{where} it concentrates.
  \item \textbf{Routing capacity.} Each region can carry a fixed number of wires. A macro blocks part of
  the routing resources above it, so a region covered by a macro has less capacity.
  \item \textbf{Overflow.} Congestion is measured as the demand that exceeds capacity:
  \begin{equation}
  \text{Overflow}=\sum_{\text{regions}}\max\big(0,\ \text{demand}-\text{capacity}\big).
  \end{equation}
  \item \textbf{The mask.} For every grid cell, the CongestionMask gives the extra overflow that would
  be created if the macro were placed there, i.e.\ if it blocked a busy routing region. This can be
  computed for the whole grid in one fast pass.
\end{itemize}
Regularity is an indirect rule (``keep macros near the edge''). The CongestionMask measures directly
what that rule tries to protect (``do not block busy routing regions''), and only where it actually
matters.

\subsubsection{Putting it together}
The regulator now receives five masks: Position, Wire and Regular from MaskRegulate, plus Timing and
Congestion. Its reward is Eq.~\eqref{eq:reward} with all four terms switched on. Setting the timing and
congestion weights to zero recovers MaskRegulate exactly, which gives us a clean baseline.

\subsection{Direction 2: multi-objective regulation}
\label{sec:d2}

\paragraph{Motivation.} Different chips need different trade-offs. A mobile chip may prioritise
wirelength and power, while a high-performance chip prioritises timing. MaskRegulate fixes one
trade-off ($\alpha=0.7$) by hand and returns a single placement. Its authors list multi-objective
optimisation as future work.

\paragraph{Goal: a menu of good placements.} Instead of one answer, we want to give the designer a
\emph{set} of placements, each representing a different trade-off. A placement is \emph{Pareto-optimal}
if no other placement is better in one objective without being worse in another. The set of such
placements is the \emph{Pareto front}, and that is what we want the regulator to produce.

\paragraph{Approach.}
\begin{enumerate}
  \item \textbf{Baseline: one regulator per trade-off.} Train separate regulators for several fixed
  weight settings $(w_{\mathrm{wire}},w_{\mathrm{reg}},w_{\mathrm{tim}},w_{\mathrm{cong}})$. This
  generalises MaskRegulate's own $\alpha$ sweep, but the training cost grows with the number of
  settings.
  \item \textbf{Proposed: one preference-conditioned regulator.} Train a \emph{single} policy that
  takes the preference weights as an extra input. During training, a new random preference is drawn
  for every batch of episodes, and the reward uses those weights. At test time, the designer chooses
  the weights, or we sweep over many of them, and the same trained model returns the matching
  placement. This follows the idea of preference-driven multi-objective RL \citep{basaklar2023pdmorl}.
  The preference is injected into the network with a simple conditioning layer (FiLM,
  \citealp{perez2018film}).
  \item \textbf{Reaching every trade-off.} A weighted sum of objectives can miss some balanced
  trade-offs. As a refinement, we will also try the \emph{Chebyshev} rule, which scores a layout by
  its worst-weighted objective. Because the final objective values are known at the end of each
  episode, this can be given as a final-step reward.
\end{enumerate}

\paragraph{How we will judge a set of placements.} We use the standard \emph{hypervolume} measure
\citep{zitzler1999hv}. It is the size of the region of objective space that the set improves upon,
relative to a fixed reference point. A set scores higher if its placements are both better and more
varied. We will evaluate on 35 evenly spread preference settings, including the four
``single-objective'' extremes \citep{das1998nbi}.

\subsection{Linking the two papers: a better starting point}
\label{sec:g3}
The regulator only edits a placement, so a better draft should lead to a better final layout. We will
therefore replace DREAMPlace's starting placement with one sampled from the pre-trained diffusion
model of Paper A. This needs no extra training. As a stretch goal, the diffusion model itself could be
fine-tuned with RL (DDPO, \citealp{black2024ddpo}), with the regulator's final improvement as the
reward. This is the future work both papers point towards.

\section{Planned Experimental Protocol}
\label{sec:protocol}

\paragraph{Benchmarks.} Our main benchmark is the ICCAD 2015 superblue suite \citep{kim2015iccad}:
eight industrial-scale designs with 0.8--1.9M cells, hundreds of macros and timing constraints. We
will also use ISPD 2005 for comparison with Paper A. Small synthetic netlists, generated with Paper A's
method, will be used for quick debugging.

\paragraph{Baselines.} DREAMPlace \citep{lin2021dreamplace}, AutoDMP \citep{agnesina2023autodmp},
MaskPlace \citep{lai2022maskplace}, MaskRegulate \citep{xue2024maskregulate} (official code) and the
pre-trained diffusion placer \citep{lee2025diffusion}.

\paragraph{Evaluation flow and metrics.}
\begin{itemize}
  \item Each method places the macros. Standard cells are then placed by DREAMPlace with the macros
  fixed.
  \item Routing and timing analysis use Cadence Innovus if a licence is available, and the open-source
  OpenROAD flow \citep{ajayi2019openroad} otherwise.
  \item \emph{Quick (proxy) metrics}: wirelength (HPWL), regularity, estimated congestion.
  \item \emph{Final (PPA) metrics}: routed wirelength, routing overflow, WNS, TNS and the number of
  violating paths.
  \item \emph{Set metrics} (Direction~2): hypervolume and the number of Pareto-optimal placements.
\end{itemize}

\paragraph{Expected challenges.}
\begin{itemize}
  \item \emph{Compute}: MaskRegulate was trained on four GPUs. We will start from released checkpoints
  and the smaller superblue designs.
  \item \emph{Tool access}: without an Innovus licence we will use the OpenROAD flow and compare
  methods relative to each other.
  \item \emph{Timing analysis cost}: if path-level timing is too slow inside training, we will use the
  cheaper critical-net weighting.
  \item \emph{Balancing objectives}: the reward weights decide which objective dominates. Direction~2
  addresses this by learning across many weightings.
\end{itemize}

\section{Conclusion}
The diffusion placer \citep{lee2025diffusion} is a fast, zero-shot drafter, and MaskRegulate
\citep{xue2024maskregulate} is an accurate RL editor. Neither lets timing or congestion guide its
optimisation, and MaskRegulate commits to a single hand-chosen trade-off. We propose two extensions:
\begin{itemize}
  \item \textbf{Direction 1:} give the regulator two new inputs and reward terms, a \emph{TimingMask}
  for critical-path delay and a \emph{CongestionMask} for routing overflow caused by macro blockage.
  \item \textbf{Direction 2:} train one preference-conditioned regulator that returns a set of
  placements covering different trade-offs, judged by hypervolume.
\end{itemize}
We will also test whether starting the regulator from a diffusion-generated placement improves the
final layout. The remaining part of the semester will be spent implementing these components and
running the planned experiments on the ICCAD 2015 benchmarks.
